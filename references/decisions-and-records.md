# 决策与记录（Decisions and Records）

## 1. 原则

1. 仓库是唯一事实源；聊天记录不作依据。
2. 讨论中达成的结论必须当场写入仓库（决策、规格、skill 或 PR 说明）。
3. 主管上下文可能被压缩或更换，所有状态必须落文件。
4. 记录中不得写入本机路径、凭据或服务器实例信息；日期使用 ISO 8601 并注明时区。

## 2. 建议的文件布局

以下为建议路径，项目可调整，但必须在开工 skill 中写明实际路径：

| 文件 | 用途 | 写法 |
|---|---|---|
| `docs/decisions.md` | 决策记录 | 只追加；结论不得改写，只能由新决策取代 |
| `docs/research/` | 调研报告 | 每份一个文件，见 `references/research.md` |
| `docs/HANDOFF.md` | 交接文档 | 只写当前有效状态，就地更新，不追加流水 |
| `plan/tasks/<任务号>.md` | 任务书副本 | 每份一个文件；改版注明修订内容 |
| `plan/dispatch-log.md` | 派单台账 | 「任务号｜执行 Agent｜回报位置｜状态｜派单日期」 |
| `plan/status-log.md` | 状态流水 | 问答、合并（PR 号与 head sha）、状态变化，按时间追加 |
| `plan/decision-ids.csv` | 决策编号索引 | 编号、标题、状态、取代关系、入库 PR |
| `plan/owner-actions.md` | 负责人事项 | 只能由负责人办理的事项；办完一项当即登记 |
| `plan/gaps.md` | 缺口清单 | 每行写第一版做法与承办者 |

## 3. 决策编号

1. 格式：`D-YYYYMMDD-NN`，日期为负责人作出决定当日（项目时区），NN 为当日序号，从 01 起。
2. 一项决定一个编号；编号一经分配不得复用。
3. 待负责人事项、任务书「依据」、审查结论引用决策时，必须使用编号。

## 4. 决策公告板

1. 项目设一个固定 Issue 作为决策公告板；可与任务书留档合一。
2. 负责人每作一项决定，主管当轮完成三步：
   1. 分配决策编号；
   2. 在公告板发一条评论（每个编号一条），字段见 §5；
   3. 到受影响的 PR 下各发一行「D-xxx 已定」。
3. 公告板不得写凭据与服务器信息；涉及时只放占位说明。
4. 执行 Agent 每次开工读取公告板自上次以来的新增条目。

## 5. 条目字段（MADR 精简）

借鉴 MADR 的字段设计，模板见 `templates/decision-entry.md`：

| 字段 | 内容 |
|---|---|
| 编号 | `D-YYYYMMDD-NN` |
| 状态 | 已定·待入库 / 已入库 #PR / 被 D-xxx 取代 |
| 事项 | 一句话说明决定的问题 |
| 决定 | 负责人原话或主管转述，注明是哪一种 |
| 决定者 | 负责人（建议人写入依据） |
| 知会 | 受影响的 PR 与 Agent |
| 验证 | 怎样算落实：测试名、规格章节或审查项；合并门第 3 项按此核对 |
| 依据 | 调研报告、规格条目、负责人原话出处 |

## 6. 取代链

1. 被取代的决策不得删除；状态改为「被 D-xxx 取代」。
2. 新条目必须写明「取代 D-yyy」，形成双向链接（参照 adr-tools 的 supersede 做法）。
3. 部分取代时写明取代范围；冲突处以较新的条目为准。
4. 规程或规格引用被取代的决策时，应在下次修改时更新引用。

## 7. 入库

1. 入库随 PR 进行：改到相关文件的作者在 PR 中把决策写入决策记录。
2. 合入后主管把公告板条目状态改为「已入库 #PR」，并更新编号索引。
3. 改契约字段、类型、枚举前，必须先有决策编号。

## 8. 任务书留档

1. 任务书全文在交负责人转发的同时，发到任务书留档（每份一条；改版发新条并注明修订内容，以最新一条为准）。
2. 执行 Agent 开工时与上下文被压缩后，从留档回读本任务书的最新一条。
3. 不访问仓库的 Agent（操作协助、资料搬运）由负责人直接粘贴任务书。

## 9. 派单台账

1. 每次派单登记一行：任务号、执行 Agent、回报位置、状态、派单日期。
2. 回报位置必须与任务书中写死的位置一致，且唯一。
3. 负责人告知「X 已回」时，主管按此登记读取。
4. 角色更换账号时，台账沿用原角色名，在备注中记录变更日期。

## 10. 交接

1. 交接文档只有一份，就地更新，不追加流水，不另开平行文档。
2. 每轮结束、主管离岗或更换前必须更新，模板见 `templates/handoff.md`。
3. 内容至少包括：main 的 head sha 与 CI 状态；新定决策；PR 状态表；已派与待派任务；待负责人事项（按优先级）；负责人本人事项；正在运行的定时任务；规则提醒。

## 11. 验收记录

每个里程碑的联调或实机验收应留一份记录（如 `docs/acceptance/<YYYYMMDD>-<里程碑>.md`），写明设备、系统版本、构建号、服务端提交与逐项结果。没有记录的里程碑不算验收完成。
