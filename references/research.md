# 调研（Research）

## 1. 先调研，再决策

1. 算法、公式、阈值、换算口径、交互结构、视觉元素，不得凭直觉决定；讨论中新出现的此类问题同样适用。
2. 交互与界面应对照成熟产品的公开做法，首要目的是查缺补漏。
3. 「尚未实现」「库中没有」只说明需要去做，不构成延后、下线或删除的理由。所有建议的第一项必须是「第一版如何做到」；确有硬性限制（法规、平台条款）时，必须引用原文并给出替代做法。
4. 调研默认派给二审与调研 Agent；文档与调研领域的执行 Agent 可承办调研报告的入库 PR。

## 2. 报告结构

1. 结论与推荐；
2. 对比表；
3. 伪代码或流程（适用时）；
4. 待定问题（逐项可由负责人一词回答）；
5. 反证检索记录（§5）；
6. 来源清单（含「来源主体」一列）；
7. 确定性评级（高 / 中 / 低 / 很低）。

## 3. 来源标准

1. 应使用：官方页面、官方文档、标准与规范、应用商店页面、实机观察或截图、论文、知名开源实现。
2. 不应使用：论坛转述、网盘资料、已过时的印刷资料。
3. 不得使用：来源不明的他人源码、泄露资料、需绕过访问控制获得的内容。
4. 只使用公开资料、实机观察与自有设计；写代码的执行 Agent 只看本项目规格。
5. 不熟悉的来源必须先查其主办方与立场；「来源主体」写不出的，按二手转述处理。

## 4. 双来源

撑起决策的关键结论，必须有两个相互独立的来源，或一个一手来源加一段可复算的推算。做不到时，结论句必须降级表述（如「据单一来源」「尚待佐证」），确定性标为低或很低。

## 5. 反证检索

每个关键结论在报告中必须有一行检索记录：关键词、检索位置、找到或未找到什么。没有此记录的报告不予通过。

## 6. 抽查与留痕

1. 报告审查由与作者不同的成员或模型执行。
2. 关键论断必须全部核查；其余论断至少抽查三分之一。
3. 抽查结果写在 PR 评论中，格式为逐条「论断 · 来源 · 判定 · 备注」，并给总评：可以依赖 / 需补证据 / 结论要改。
4. 主管至少亲自打开一条来源 URL 核对；回报中引用的每处决策都核对原文。不实情况记入审计记录，并在 PR 下指出。

## 7. 更正

1. 报告合入后发现错误，必须在原文出错处标注更正（日期与原因），不得静默修改。
2. 补证据只补不改结论；结论需要改变的，交主管决定，必要时请负责人决定并登记决策编号。

## 8. 引用规则

1. 建议中凡写「某成熟产品也这样做」，必须附本轮实际打开过的 URL，或回报中已附 URL 的出处。
2. 找不到先例时明说「无先例，理由是……」。
3. 不得编造供应商、版本、年限、选项。
