# 设计（Design）

## 1. 分工

1. 设计类任务（token、样张、图标、界面稿、视觉规范）一律派给设计系统执行 Agent。
2. 客户端界面实现应引用已定稿的样张；后端与不依赖视觉的工作可并行推进。

## 2. 先立标准，再出图

1. 出图前先调研目标品质（如「简约、高级、有质感」）的成熟产品先例，形成可核对的标准。
2. 执行 Agent 按标准出图，主管按同一标准验图。

## 3. 设计待定清单

1. 派设计单前，主管必须列出待定清单：界面上每个元素占一行，字段为「规格章节｜token｜先例与 URL｜自查」。
2. 每行必须有出处；任何一行为空时不得派单。
3. 空行先调研，再逐项（一次一问）请负责人决定。
4. 必须看图才能选择的项，在同一版中并排出样张供负责人比较，不分多轮出图。

## 4. token 一致性

1. 每个元素都必须有出处，数值落在 token 表中，不得在界面稿中直接写未登记的数值。
2. 新 token 必须与既有 token 的美学一致（比例、色彩关系、圆角、阴影体系）。
3. 不得以「现有 token 未覆盖」为由删减方案；应补 token 并走审查。
4. 未定项标「待定」，不得新造数值填充。

## 5. 图标与素材许可

1. 图标优先使用成熟开源图标库；使用前核对许可证并按要求署名。
2. 同一界面画法必须统一（栅格、线宽、端点与圆角）。
3. 库中缺少的图标，先在同源库中查找；仍无时按该库的官方设计规范自绘。
4. 字体、图片等素材同样核对许可证，记录来源。

## 6. 文化自查

涉及文化元素（节令、色彩寓意、数字、手势、符号等）时，必须过两项自查并记录结论：

1. 目标市场的民俗忌讳；
2. 符号误读风险。

## 7. 探索稿与定稿

1. 探索稿只作参考，不进 main，文件或图名标「探索稿」。
2. 负责人确定后，当日写入定稿记录（定稿编号、日期、决定者、影响的 token 与组件），开 PR 过合并门。
3. 客户端实现与设计交接必须引用定稿编号，否则可拒收。
4. 会触发发布构建的任务，验收应写明 token 版本、设计定稿编号与占位清单（每条写原因与补齐任务）。

## 8. 交付前主管逐张验图

设计交付后，主管必须逐张检查，全部通过后方可转给负责人：

1. 元素遮挡、文字截断或溢出；
2. 内部术语或占位文字出现在界面上；
3. 点击区域小于平台最小尺寸（如 44pt）；
4. 颜色对比度不足；
5. 与 token 表、定稿编号不一致；
6. 落脚点与界面用语两项（同合并门第 7、8 项）。

不通过的退回设计系统执行 Agent，并附逐张问题清单。
