# 审查结论模板（Review）

> 使用说明：一审与二审结论均发在被审 PR 评论中，以评论为正本。评论中的「通过」不等于合并授权。

```markdown
# <审查编号> <一审 / 二审> · #<PR 号> · head <sha>

- 审查范围：<全量 / 增量（自 <sha> 起）>；比对 main：<sha>
- 修正单核对：<逐条：已落实 / 未落实>

| 栏目 | 结论 |
|---|---|
| 覆盖 | 变更文件 <n> 个，逐行读 <n> 个；生成物与二进制：<处理方式> |
| CI | run <id>；jobs：<名称与结果>；环境故障：<有 / 无> |
| 自报缺口 | <逐条：已关闭 / 待豁免 / 未处理> |
| 二审 | <需要 / 不需要>（类别：<…>） |
| 新鲜度 | 审查 head <sha> 与当前 head <一致 / 不一致> |
| 体量 | <n> 文件 / <n> 行；<无需拆分 / 已说明> |
| 规格符合 | <符合 / 偏差：…> |
| 落脚点 | <位置 / 缺失（退回）> |
| 界面用语 | <合规 / 问题：…> |

## 问题
| 编号 | 级别 | 位置 | 问题 | 建议 |
|---|---|---|---|---|
| R1 | Critical / Important / Minor | <文件:行> | <…> | <…> |

## 结论
<可合并 / 带条件通过（条件：C1 …） / 不可合并>

## 证据
<本次亲自运行或打开的命令、日志、URL；未核实项标「未验证」>
```

二审追加：调研类报告的抽查按「论断 · 来源 · 判定 · 备注」逐条列出，并给总评（可以依赖 / 需补证据 / 结论要改）。
