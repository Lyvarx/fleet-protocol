# 任务书模板（Task Brief）

> 使用说明：尖括号内为填写项。任务书必须能脱离对话独立读懂；首行与文末三行不得删除。

```markdown
请先加载项目开工 skill「<开工 skill 名称>」；未安装该 skill 的，按文末开工规程执行。

# 任务 <任务号>：<一句话目标>

- 承办：<执行 Agent 角色名>
- 分支：task/<任务号>-<短名>（基线：<最新 main / 指定分支>；单独开草稿 PR）
- 排期：<立即 / 在 <任务号> 之后>
- 依据：<决策编号、规格章节、调研报告路径>
- 允许修改：<目录或文件>
- 禁止修改：<目录或文件>；共享文件（契约、CI 配置、token）同一时间只由一个任务持有
- 在制品：派单时开着的 PR 为 <n>/<上限>
- 二审：<需要 / 不需要>（理由：<所属二审范围类别或「不属于二审范围」>）

## 负责人原话
<负责人的原话，一字不改；主管不得改写、不得据此加活>

## 主管补充
<做法与范围；只补怎么做，不扩大范围>

## 怎么验（必填）
<可运行的命令或可核对的结果>

## 权限多大（必填）
<可改的文件与可做的操作；不可撤操作、部署、密钥、对外发布须单列并注明须负责人授权>

## 出发点
<为什么做：负责人原话或决策编号>

## 落脚点
<产出在哪里被读取、用户看到什么结果：规格文件与章节，或界面位置>

## 要做
1. <步骤>
2. <步骤>

## 约束
- <技术约束、兼容性、性能要求>
- 界面文字：<列出需保留的品牌化口语句；其余使用成熟商业表达>

## 验收
- [ ] 测试先行：先提交失败测试，再提交实现
- [ ] 可运行命令：`<命令>`，期望输出：<描述>
- [ ] PR 上 CI 汇总检查通过
- [ ] <具体覆盖点>

## 停手条件
同一原因失败两次；需要修改允许范围以外的文件；与已定决策冲突；缺少凭据或权限；判定为环境故障；在制品已达上限。停在最近一个完整提交并按下述位置上报。

## 回报
- 位置（唯一）：<PR 描述与 PR 评论 / 任务书留档 Issue 评论>
- 标题：「<任务号> 回报 · head <sha>」
- 格式：templates/report.md
负责人只需告知主管「<任务号> 已回」。

---
开工规程：
1. 列出自己开着的 PR，读上次回报之后的新评论与决策公告板新增条目；
2. 先按评论与修正单执行，再做手头的任务书；
3. 冲突时以较新的主管指令为准；无法判断时停手上报。
```
